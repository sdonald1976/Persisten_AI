# Reranker shadow — the first specialist, observable and reviewable

The cross-encoder memory reranker runs in **shadow** beside the authoritative 3B reranker and
the deterministic rule baseline. It changes no displayed turn. This is the integrated,
observable, reviewable product for Scott's testing this week; it does **not** promote or
fine-tune anything.

## What runs, and what is authoritative

On every eligible retrieval (both routes — retrieval is upstream of the Stheno/mouth split):

- **authoritative:** `LlmMemoryReranker` (qwen3b). Its ordering is the one the turn uses.
- **shadow:** `CrossEncoderMemoryReranker` (22M ONNX, `reranker.onnx`, CPU ~25 ms) and
  `RuleBasedMemoryReranker`. Recorded, never displayed.

`ShadowComparingReranker` returns the authoritative result first and unguarded, then runs the two
shadow methods each under a 3 s timeout in their own try/catch. A shadow failure or timeout is
recorded and the turn continues — proven by `ShadowComparingRerankerTests` (throwing shadow, slow
shadow, private turn, no scope, single candidate). Records hold candidate **ids and orderings
only** — no memory or query text — and are skipped entirely on private/sensitive turns.

## The configuration switch

`appsettings.json` → `Companion:CognitiveModels`:

| flag | meaning |
|---|---|
| `Reranker.Enabled` | load the cross-encoder ONNX (needed for shadow **and** promotion) |
| `RerankShadow` | run the tri-way shadow comparison and record it (**this iteration: on**) |
| `RerankMemories` | make the **cross-encoder authoritative** — this is PROMOTION, left **off** |

- **Shadow (now):** `Reranker.Enabled=true`, `RerankShadow=true`, `RerankMemories=false`.
- **Promotion (later, gated):** flip `RerankMemories=true`. One flag. Do not, until the report's
  gate is met.

## Rollback (verified)

Set `CognitiveModels:RerankShadow=false` (or `Reranker.Enabled=false`) and restart → the shadow
stops, the 3B remains authoritative exactly as before. If promotion is ever tried and regresses,
set `RerankMemories=false` → instant return to the 3B. Both are single-flag, no other change.
`demo-user`'s guard-critical mouth route is independent and untouched by any of this.

## Run it

```
tools\shadow\shadow-start.ps1     # mouth (:11436) + API (:5266) with RerankShadow on
tools\shadow\shadow-smoke.ps1     # drive representative turns → shadow records
tools\shadow\shadow-report.ps1    # generate the comparison report
tools\shadow\shadow-stop.ps1      # stop everything this package started (leaves VS alone)
```

Review the recorded comparisons and add human relevance labels:

```
python training\cognition\rerank_review.py            # review, most-informative first
python training\cognition\rerank_review.py --export   # versioned, user-grouped dataset
```

## The report

`training\cognition\rerank-shadow\RERANK_SHADOW_REPORT.md`, regenerated by `shadow-report.ps1`:
top-1/top-3 agreement between all three methods, latency **distributions** (p50/p90/p99/max, not
just averages), failure/fallback rates, and — once reviewed labels exist — P@1/R@3/MRR per method
with a **paired, conversation/user-grouped bootstrap** CI on the cross-encoder-minus-3B
difference (resampling whole users, since turns cluster by user). An independent-proportion CI is
context only; the grouped paired bootstrap is what the gate reads.

## Promotion gate (conservative — not met yet)

1. the cross-encoder must not lose to the rule floor on any sufficiently-populated user-grouped fold;
2. it must match or beat the 3B on the frozen, reviewed **real** set (paired CI ≥ 0);
3. its latency p99 and failure rate must support replacing the live 3B call;
4. weak/mechanical/synthetic/borrowed labels may guide collection and debugging but **cannot**
   independently authorize promotion.

## Honest limitations, today

- **Real reviewed labels are the bottleneck, not infrastructure.** The live DB holds single-digit
  turns; the pipeline is proven end-to-end on synthetic data (see the eval's synthetic run: it
  computes P@1/R@3/MRR, agreement, latency distributions, and a grouped paired bootstrap CI
  correctly). Real promotion waits on accumulated review, and the report says so on every run.
- **Scores are not surfaced through `IMemoryReranker`.** Rankings drive every metric; per-item
  cross-encoder scores would need the reranker to annotate results, deferred.
- **The 3B appears only in the real shadow stratum.** Synthetic/borrowed strata (which lack a 3B
  ranking) are reported separately and never mixed into the reviewed-real numbers.
- **Provenance and reranker-shadow are id-only.** Text is joined locally at review time from
  `companion.db`; nothing sensitive is duplicated, and private turns never enter either store.
